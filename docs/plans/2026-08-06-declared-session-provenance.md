# Declared Session Provenance Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Stop suppressing lgtm's routine notifications by guessing at LLM-generated session titles; record provenance at spawn time in a sticky store and read it at notification time.

**Architecture:** A new `session_origin` table in the daemon's SQLite DB, deliberately decoupled from the `sessions` table (which the plugin overwrites on every re-registration) and from every existing cleanup sweep (the row must outlive the session so a re-awakened session stays quiet). One idempotent auth'd endpoint, `POST /session-origin`, with insert-or-keep semantics and a `declared > inferred` source precedence. Two declared writers — `opencode-launch` (ordering-correct: fires between session creation and first prompt) and lgtm's own dispatch loop (backstop for the degraded launch path). The `/stop` reader consults an explicit per-event policy matrix. The existing title regex stays behind a flag until a fired-counter proves it is dead.

**Tech Stack:** TypeScript, Node 22, better-sqlite3, vitest (pigeon daemon); bash + nix (`opencode-launch` in the `workstation` repo); TypeScript + vitest (`lgtm`).

**Beads:** epic `pigeon-qdcb`, tasks `pigeon-qdcb.1` … `pigeon-qdcb.6`.

## Background — read this before touching anything

### The failure this replaces

`packages/daemon/src/app.ts:115` defines `DEFAULT_QUIET_TITLE_PATTERN`, a regex matched
against the session **title** at `app.ts:700`. Titles are generated by the model, so the
mechanism is inferential. The comment at `app.ts:93-114` records honest measurement:
96.6% catch across 181 production titles, 0 false positives.

The leak that motivated this work:

```
session_id: ses_028e8009bffeFjD1ejvf7ZrAVk
title:      'PR review'
cwd:        /home/dev/projects/culinary-operations-server/.worktrees/pr-4618
notify:     1
```

No `lgtm` token in the title. Nothing to tune.

A **cwd**-based filter is also a dead end, already documented in
`docs/plans/2026-07-31-delivery-hardening-roadmap.md:967-973`: lgtm-dispatched sessions
run in ~32 distinct worktrees, none of them under `~/projects/lgtm`. Only the dispatcher
itself lives there — and a human doing genuine work on the lgtm tool in
`~/projects/lgtm` **must still be notified**.

### Five facts that constrain the design

1. **`sessions.notify` cannot hold the verdict.** The plugin hardcodes `notify: true`
   when registering (`packages/opencode-plugin/src/daemon-client.ts:136`), `/session-start`
   writes `body.notify` straight through (`app.ts:578`), and the outbox sender
   re-registers sessions during recovery. Anything stored there gets clobbered. Hence a
   separate table.

2. **`POST /place` is *not* called by `opencode-launch`.** An earlier draft of this design
   assumed it was. It is not — the launcher does a read-only `GET /route`
   (`pkgs/opencode-launch/default.nix:389`, deployed script line 381), with `|| true` and a
   2s timeout. `/place` is called by `oc-auto-attach`/`oc-pool-attach`, only on a `/route`
   miss, *after* the prompt is delivered. It is also the wrong host for provenance: it
   fails 503/409 in routing-specific ways (`app.ts:941-966`) precisely in the degraded
   scenarios that matter, and repo history (pigeon-eup, see the comment at
   `app.ts:977-986`) says explicitly: do not smuggle writes into routing endpoints.

3. **`Error` and `Retry` ride the same `POST /stop`** (plugin `index.ts:543,652`). Today's
   gate tests `event === "Stop"` (`app.ts:700`), so lgtm **errors and retries are currently
   delivered**. A naive policy reader that suppresses all `/stop` traffic is a silent
   regression, and the migration counter would not catch it because the title layer would
   have passed them too. This is why the reader needs an explicit matrix.

4. **A quieted session has no Telegram message to swipe-reply to**, so the user has no
   lever to un-quiet it. `POST /sessions/enable-notify` (`app.ts:605`) only writes
   `sessions.notify`, which the new reader would override. The override path is not
   optional polish; it is the escape hatch.

5. **tmux-based inference is out of scope.** It was in an earlier draft and adversarial
   review killed it. The walker (`packages/daemon/src/main-session-allowlist.ts:70,105`)
   observes `opencode attach` **client processes**, not sessions. The nightly reset tears
   down tmux `lgtm` (`~/projects/lgtm/src/dispatch.ts:17-20`) and re-awakening goes through
   `/swarm/send` with no new attach pane — so the layer fails exactly on the recurring
   re-review path it was meant to cover, and caching its verdict from that transient state
   poisons the row permanently. Do not add it. If a later fired-counter proves a real
   residue, revisit with positive-only caching and a TTL.

### Fail-open is the house rule

`app.ts:113`: "a false positive silently hides real work, so ambiguity resolves toward
delivering." Every new code path must preserve that. Writer unreachable → no row → deliver.
Unknown policy string → deliver. Malformed row → deliver.

```ts
import type BetterSqlite3 from "better-sqlite3";

/**
 * Declared provenance for a session, recorded by whoever spawned it.
 *
 * Deliberately NOT part of `initSchema`'s sessions DDL and deliberately WITHOUT a
 * foreign key to sessions(session_id).
 *
 * Two independent reasons, both load-bearing:
 *
 *  1. The `sessions` row is rewritten wholesale on every plugin registration, and the
 *     plugin hardcodes notify: true (opencode-plugin/src/daemon-client.ts:136). A verdict
 *     stored there is clobbered on the next outbox recovery.
 *
 *  2. The row must OUTLIVE the session. The session reaper (session-reaper.ts:31-35) and
 *     dead-session cleanup (worker/command-ingest.ts:1085,1150) both delete the sessions
 *     row, and lgtm then re-awakens the same session id through /swarm/send. If the
 *     provenance went with it, every re-review would go loud again.
 */
export function initSessionOriginSchema(db: BetterSqlite3.Database): void {
  db.exec(`
    CREATE TABLE IF NOT EXISTS session_origin (
      session_id TEXT PRIMARY KEY,
      origin TEXT NOT NULL,
      notify_policy TEXT NOT NULL,
      source TEXT NOT NULL,
      created_at INTEGER NOT NULL,
      updated_at INTEGER NOT NULL
    );

    CREATE INDEX IF NOT EXISTS idx_session_origin_origin ON session_origin(origin);
  `);
}
```

**Step 4: Write the repository**

Create `packages/daemon/src/storage/session-origin-repo.ts`:

```ts
import type BetterSqlite3 from "better-sqlite3";

/** Ordered weakest-to-strongest. A write never lowers the stored source. */
export const ORIGIN_SOURCES = ["inferred", "declared"] as const;
export type OriginSource = (typeof ORIGIN_SOURCES)[number];

/**
 * `all`         — deliver every event (the default for anything with no row).
 * `errors-only` — suppress routine Stop; still deliver Error and Retry.
 * `none`        — suppress Stop, Error and Retry alike.
 *
 * An unrecognised value read back from the DB is treated as `all`: ambiguity resolves
 * toward delivering (app.ts:113).
 */
export const NOTIFY_POLICIES = ["all", "errors-only", "none"] as const;
export type NotifyPolicy = (typeof NOTIFY_POLICIES)[number];

export function isNotifyPolicy(value: unknown): value is NotifyPolicy {
  return typeof value === "string" && (NOTIFY_POLICIES as readonly string[]).includes(value);
}

export function isOriginSource(value: unknown): value is OriginSource {
  return typeof value === "string" && (ORIGIN_SOURCES as readonly string[]).includes(value);
}

export interface SessionOriginRecord {
  sessionId: string;
  origin: string;
  notifyPolicy: NotifyPolicy;
  source: OriginSource;
  createdAt: number;
  updatedAt: number;
}

export interface RecordSessionOriginInput {
  sessionId: string;
  origin: string;
  notifyPolicy: NotifyPolicy;
  source: OriginSource;
}

function rank(source: OriginSource): number {
  return ORIGIN_SOURCES.indexOf(source);
}

export class SessionOriginRepository {
  constructor(private readonly db: BetterSqlite3.Database) {}

  /**
   * Insert-or-keep. A write from a weaker source never overwrites a stronger one, so a
   * later inferred guess can never downgrade what the launcher declared. Equal-or-stronger
   * writes refresh the payload and updated_at but preserve created_at.
   */
  record(input: RecordSessionOriginInput, now = Date.now()): void {
    this.db.prepare(
      `INSERT INTO session_origin (
         session_id, origin, notify_policy, source, created_at, updated_at
       ) VALUES (?, ?, ?, ?, ?, ?)
       ON CONFLICT(session_id) DO UPDATE SET
         origin        = CASE WHEN excluded.source_rank >= source_rank THEN excluded.origin ELSE origin END,
         notify_policy = CASE WHEN excluded.source_rank >= source_rank THEN excluded.notify_policy ELSE notify_policy END,
         source        = CASE WHEN excluded.source_rank >= source_rank THEN excluded.source ELSE source END,
         updated_at    = excluded.updated_at`,
    );
    // NOTE: SQLite has no `source_rank` column; the CASE comparisons above are written
    // against a rank computed in TypeScript instead. See the real statement below.
  }

  get(sessionId: string): SessionOriginRecord | null {
    return null;
  }

  clear(sessionId: string): boolean {
    return false;
  }
}
```

> **Implementer note:** the `record` body above is intentionally left as a sketch with a
> dead-end SQL comment — do **not** ship it. Ranking cannot be done in the `ON CONFLICT`
> clause without a stored rank column. Implement it as a read-then-write inside a
> `db.transaction(...)`, which is clearer and equally safe under better-sqlite3's
> synchronous single-connection model:
>
> ```ts
> record(input: RecordSessionOriginInput, now = Date.now()): void {
>   const tx = this.db.transaction(() => {
>     const existing = this.get(input.sessionId);
>     if (existing && rank(input.source) < rank(existing.source)) return;
>     if (existing) {
>       this.db.prepare(
>         `UPDATE session_origin
>             SET origin = ?, notify_policy = ?, source = ?, updated_at = ?
>           WHERE session_id = ?`,
>       ).run(input.origin, input.notifyPolicy, input.source, now, input.sessionId);
>       return;
>     }
>     this.db.prepare(
>       `INSERT INTO session_origin (session_id, origin, notify_policy, source, created_at, updated_at)
>        VALUES (?, ?, ?, ?, ?, ?)`,
>     ).run(input.sessionId, input.origin, input.notifyPolicy, input.source, now, now);
>   });
>   tx();
> }
> ```
>
> `get` reads the row and coerces `notify_policy` through `isNotifyPolicy` (unknown → `all`)
> and `source` through `isOriginSource` (unknown → `inferred`). `clear` runs a `DELETE` and
> returns `result.changes > 0`.

```ts
if (request.method === "POST" && url.pathname === "/session-origin") {
  const body = await readJsonBody(request);
  const sessionId = typeof body.session_id === "string" ? body.session_id : "";
  if (!/^ses_[A-Za-z0-9_-]+$/.test(sessionId)) {
    return Response.json({ error: "session_id must match ^ses_[A-Za-z0-9_-]+$" }, { status: 400 });
  }

  const origin = typeof body.origin === "string" ? body.origin.trim() : "";
  if (!origin) {
    return Response.json({ error: "origin is required" }, { status: 400 });
  }

  // Reject rather than default. On the READ path an unknown policy degrades to "all"
  // (deliver), because a corrupt row must never silence real work. On the WRITE path
  // the opposite is right: a typo'd policy that silently became "all" is
  // indistinguishable from the feature not being deployed.
  const notifyPolicy = body.notify_policy;
  if (!isNotifyPolicy(notifyPolicy)) {
    return Response.json(
      { error: `notify_policy must be one of: ${NOTIFY_POLICIES.join(", ")}` },
      { status: 400 },
    );
  }

  // Deliberately NOT gated on the session existing. The launcher writes between
  // session creation and the first prompt, which is BEFORE the plugin registers the
  // session with the daemon — that ordering is the whole point of the launcher writer.
  storage.sessionOrigins.record(
    { sessionId, origin, notifyPolicy, source: "declared" },
    nowFn(),
  );

  console.log(`[session-origin] declared sessionId=${sessionId} origin=${origin} policy=${notifyPolicy}`);
  return Response.json({
    ok: true,
    session_id: sessionId,
    origin,
    notify_policy: notifyPolicy,
    source: "declared",
  });
}
```

Create `packages/daemon/src/notify-policy.ts`:

```ts
import { isQuietTitle } from "./app";
import type { NotifyPolicy } from "./storage/session-origin-repo";

export type NotifyLayer = "origin" | "title" | "default";

export interface NotifyDecisionInput {
  event: string;
  policy: NotifyPolicy | null;
  title: string | null | undefined;
}

export interface NotifyDecision {
  deliver: boolean;
  layer: NotifyLayer;
}

/** Events that `errors-only` still delivers. */
const ERROR_EVENTS = new Set(["Error", "Retry"]);

/**
 * Which notification layer decided, and what it decided.
 *
 * Precedence, strongest first:
 *   1. session_origin.notify_policy  (declared provenance)
 *   2. the legacy quiet-title regex  (transitional; disable with
 *      PIGEON_QUIET_TITLE_LAYER=off, delete under pigeon-qdcb.5)
 *   3. deliver
 *
 * The caller checks `sessions.notify` BEFORE calling this (app.ts:684); that short-circuit
 * is upstream of the whole matrix.
 *
 * Every unnamed case delivers. `Error` and `Retry` arrive on the same POST /stop as `Stop`
 * (opencode-plugin/src/index.ts:543,652), and have always been delivered for lgtm sessions
 * because the old gate tested `event === "Stop"`. Silencing them here would be a
 * regression that no counter would surface.
 */
export function decideNotify(
  input: NotifyDecisionInput,
  env: Record<string, string | undefined> = process.env,
): NotifyDecision {
  const { event, policy, title } = input;

  if (policy === "none") {
    if (event === "Stop" || ERROR_EVENTS.has(event)) return { deliver: false, layer: "origin" };
    return { deliver: true, layer: "origin" };
  }

  if (policy === "errors-only") {
    if (event === "Stop") return { deliver: false, layer: "origin" };
    return { deliver: true, layer: "origin" };
  }

  if (policy === "all") return { deliver: true, layer: "origin" };

  const titleLayerOn = (env.PIGEON_QUIET_TITLE_LAYER ?? "on").trim() !== "off";
  if (titleLayerOn && event === "Stop" && isQuietTitle(title, env)) {
    return { deliver: false, layer: "title" };
  }

  return { deliver: true, layer: "default" };
}
```

```ts
/**
 * Best-effort: tell pigeon this session is ours so its routine Stop notifications stay
 * out of Telegram. Never throws — a pigeon outage must not fail a dispatch, and the
 * worst case is a notification the user did not want, not a review that did not run.
 *
 * This is the BACKSTOP writer. The ordering-correct one is opencode-launch's --origin
 * flag, which fires before the first prompt; this one fires after, so a session that
 * dies instantly can still emit one Stop first.
 */
async function markOrigin(sessionId: string): Promise<void> {
  if (!sessionId) return; // parseLaunchOutput failed; nothing to key on
  try {
    const headers: Record<string, string> = { "content-type": "application/json" };
    const token = resolvePigeonToken();
    if (token) headers["Authorization"] = `Bearer ${token}`;
    const res = await fetch(`${PIGEON_DAEMON_URL}/session-origin`, {
      method: "POST",
      headers,
      body: JSON.stringify({
        session_id: sessionId,
        origin: "lgtm",
        notify_policy: "errors-only",
      }),
      signal: AbortSignal.timeout(3_000),
    });
    if (!res.ok) log(`WARNING: pigeon /session-origin returned ${res.status} for ${sessionId}`);
  } catch (err) {
    log(`WARNING: pigeon /session-origin failed for ${sessionId}: ${String(err)}`);
  }
}
```
